## 文件夹结构

面板所有数据都放在 `panel.exe` 所在的文件夹里：

```text
server/                 官方服务器文件
userdata/               本地游戏数据
backups/config/         配置备份
backups/userdata/       userdata ZIP 备份（userdata-auto-* 为计划任务创建）
backups/before-restore/ 恢复备份前被替换下来的 userdata（保留 3 份）
cache/                  Sandbox 定义缓存、见过的玩家（players.json）
logs/                   面板与服务器日志
tools/steamcmd/         SteamCMD
```

首次在“概览”的“环境检查”中创建本地目录，并可一键把 `UserDataFolder` 指向这里的 `userdata`。
侧栏底部可以切换简体中文、繁體中文和 English，以及跟随系统、浅色或深色主题，选择保存在当前浏览器。
游戏配置页的参数名称优先使用官方 `Localization.csv` 的译文，原始 XML 键始终显示在名称下方。

## 启动与停止

启动后服务器先显示为“正在启动”，直到日志出现 `StartGame done`（世界加载完成）或 Telnet
能够应答才变为“运行中”；如果 10 分钟内都没有这两个信号，也会自动转为“运行中”。
加载期间不能正常停止（正常停止依赖 Telnet），但可以强行停止。

“正常停止”通过 Telnet 请求服务器保存数据后退出，最长等待 2 分钟。“强行停止”在服务器处于
正在启动、运行中、正在停止、停止超时或异常退出，且服务端发放一次性确认令牌时可用；需要确认，
并应仅在正常停止无效时使用，因为可能丢失未保存的数据。

每次启动前，上一次运行的 `logs\server-current.log` 会被改名为 `logs\server-<时间>.log`
保留下来（最多 5 份），方便排查崩溃原因。

## 更新

服务器页包含两项更新操作：“更新游戏服务器”通过 SteamCMD 运行 App ID `294420` 并使用
`validate` 验证文件；“更新 SteamCMD”会在其缺失时下载它，或在已安装时运行 `+quit` 自更新。
两项操作都不会自动停止或启动游戏服务器。

“游戏版本与分支”可以选择安装的 Steam 分支：稳定版 `public`、实验版 `latest_experimental`，
或任意分支名（例如固定在旧版本 `alpha21.2`），需要时填写分支密码（`-betapassword`，保存在
`panel.json`，不会返回给浏览器）。选“默认”时不传 `-beta`，与旧版本行为相同。切换分支后停止游戏
并点“更新游戏服务器”即可。

更新提醒：面板每天检查一次 GitHub 上的新版本，每 6 小时用 SteamCMD（`app_info_print`）检查一次
所选分支的最新 build，并与 `server\steamapps\appmanifest_294420.acf` 中已安装的 build 比较；
发现新版本时在活动记录里提示一次。可在服务器页关闭自动检查，也可随时手动检查。

## 计划任务

“计划任务”页可以添加：

- **重启游戏**：在每天固定时间（可选星期）或每隔 N 分钟，先在游戏内用 `say` 倒计时公告
  （例如提前 10、5、1 分钟，文字可自定义，`{minutes}` 替换为分钟数），再通过 Telnet 正常关服并重新启动；
- **备份**：游戏运行时先 `saveworld` 再备份（“热备份”），停止时直接备份；自动备份命名为
  `userdata-auto-*`，按“保留份数”自动清理，手动备份永不自动删除；
- **控制台命令**，例如定时 `saveworld`；**公告**：定时全服广播。

还可以勾选“游戏崩溃后自动重启”（崩溃 10 秒后重启，30 分钟内超过 3 次则停止，避免坏 Mod 或存档
无限循环），以及“面板启动时自动启动游戏”——配合“面板”页的“开机自动启动面板”，电脑重启后
服务器会自动开服。时间按面板所在电脑的本地时间；电脑睡眠等原因错过超过 5 分钟的任务会跳过，
不会补做。计划任务保存在 `panel.json` 的 `schedule` 中，随面板运行（停止面板即暂停）。

## 玩家管理

“玩家”页在游戏运行时通过 Telnet `lp` 列出在线玩家（平台 ID、等级、延迟、IP），可以私聊、踢出、
限时封禁；按平台 ID（`Steam_…`、`EOS_…`、`XBL_…`）为离线玩家加入白名单、设为管理员或封禁；
全服公告。所有操作都是游戏自带的控制台命令（`kick`、`ban add/remove`、`whitelist`、`admin`、
`say`、`sayplayer`）。管理员、白名单和封禁列表读取自游戏的 `serveradmin.xml`；面板还会记住
游戏运行期间见过的玩家（`cache\players.json`），方便对离线玩家操作。

### NaiwaziBot

[NaiwaziBot](https://www.7risha.com/7038.html) 是很多租服面板自带的服务端 Mod，提供积分商店、传送、
签到等玩家功能和自己的网页后台（默认端口为游戏端口 + 6），文档见 <http://cn.naiwazi.com/bot/>。
它**永久免费但不开源**：[GitHub 仓库](https://github.com/Naiwazi/NaiwaziBot) 只有一个 README，没有源码和许可证；
发布包里的核心是混淆过的 .NET 程序集，并且会连接作者的云端存储和自动更新。因此本面板**不内置、不分发**它。
像其他 Mod 一样在“Mod 管理”页上传它的 ZIP 即可安装；安装后“玩家”页会检测到它，显示版本、端口
和是否在监听，可一键打开它的后台、查看它写入的登录信息文件（`server\NaiwaziBot_Data\NaiwaziBot_Password.txt`），
端口不是默认值时可以手动指定。注意它的后台监听所有网卡，不受本面板“只允许本机访问”的保护。

## 性能监视

“概览”页每 2 秒显示一次主机 CPU、GPU、内存以及游戏进程的 CPU 与内存占用，并绘制最近 60 秒的曲线。
数据直接读取 Windows 性能计数器（与任务管理器相同的来源），不需要额外安装或启动任何组件；
只在打开“概览”页时采样，不保存长期历史、不提供告警，也不读取温度。

GPU 使用率需要显卡驱动提供 GPU Engine 性能计数器。某些 Windows Server 安装的性能计数器可能损坏或
被禁用，此时可在管理员命令行运行 `lodctr /R` 重建。

## 世界与存档

“世界与存档”页会列出世界和存档、当前使用项及缺失项。切换、导出、导入和删除只在
服务器停止时可用。导出产生只包含所选世界和存档的 ZIP 整包；导入只接受一个 ZIP
整包；删除前会先建立 ZIP 备份。

## 备份与恢复

“备份”页为整个 `userdata` 创建 ZIP 备份。游戏运行时会先执行 `saveworld` 再复制文件；停止时直接备份。
每个备份都可以一键**恢复**（需要先停止游戏）：备份会解压到临时目录，当前的 `userdata` 被移动到
`backups\before-restore\userdata-<时间>` 保留（最多 3 份），再换上恢复的数据；如果换入失败会自动换回。
也可以删除不需要的备份。定时自动备份在“计划任务”页设置。

## 游戏配置与本地化

“游戏配置”保留原始 XML 属性、顺序和注释。字段标签及说明优先读取官方
`server/Data/Config/Localization.csv` 的 English、简体中文和繁体中文文本；未覆盖的
专用服务器键由内置中英对照补充，仍无文本时才退回原始属性名。内置中文说明只用于可
核对的条目，未知说明保持为空。

## SandboxCode

原始 `SandboxCode` 总能编辑。当前服务器运行且本地缓存与服务器 build 完全匹配时，
页面显示受官方 Dashboard `SandboxSettings` 定义约束的可视化控件：改动已存在记录的
控件会立即更新原始代码；输入有效原始代码会立即更新定义中存在的控件。未知记录和
原有记录顺序会保留。

只有点击一个“保存”按钮才会写入配置。纯可视化改动提交精确的选项改动；手动输入的
有效原始代码按原样提交。无可用或不匹配定义时是原始模式，不显示可视化控件，也不会
自动重写代码。无效代码会指出记录/字符位置并禁用保存。缓存不匹配时会为该 build 自动
尝试一次刷新；Dashboard 要求认证时才显示“控制面板令牌名称”和“控制面板令牌密钥”
输入框。面板将它们作为 `X-SDTD-API-TOKENNAME` 与 `X-SDTD-API-SECRET` 请求头发送给
本机官方 Dashboard；它们只保存在当前页面内存，成功刷新后即清空，不会存入面板、日志
或缓存。

## 服务、停止与升级

Windows 服务直接由 `panel.exe` 管理，不再需要脚本（旧版本的 `scripts\` 已删除）：

- **双击 `panel.exe`**：没有安装服务时，面板在控制台窗口运行并打开浏览器；安装了服务时，启动服务并
  打开浏览器（服务指向另一个 `panel.exe` 时会弹出管理员确认把它更新为当前程序）。以管理员身份运行时
  始终在控制台窗口运行，用于应用防火墙等需要管理员权限的操作。
- **“面板”页**：显示版本、运行方式、面板文件夹；“安装为服务并切换”“更新服务”“卸载服务”（弹出
  UAC 确认）；“开机自动启动面板”（延迟自动启动）；“停止面板”。
- **命令行**：`panel.exe service install`、`panel.exe service uninstall`、
  `panel.exe service autostart on|off`（会自动请求管理员权限），`panel.exe --console` 强制在控制台运行。

服务以独立的虚拟账户 `NT SERVICE\7DTDserverPanel` 运行，只被授予面板文件夹的修改权限，
而不是 SYSTEM 账户；游戏服务器和 Mod 继承这个受限身份。交互式登录的用户可以启动和停止服务（双击
`panel.exe` 不需要管理员确认），只有管理员能修改服务配置。因此以服务运行时面板没有管理员权限：
防火墙页只能预览，“开机自动启动面板”也不能在网页里切换（可在面板文件夹运行
`panel.exe service autostart on`）。要应用防火墙更改，请在“面板”页停止面板，右键 `panel.exe`
选择“以管理员身份运行”，应用后关闭它，再双击 `panel.exe` 回到服务。

停止面板只停止网页、轮询、计划任务和日志尾随，**不会停止游戏**；服务器页的“正常停止”和
“强行停止”分别是游戏的正常与强制停止操作。升级前请先创建 userdata 备份。

如果浏览器没有自动打开，请查看 `logs\panel.log` 或手动访问面板启动日志显示的
`http://127.0.0.1:<port>`。

## 防火墙、Mod 与控制台

防火墙只管理面板拥有的入站规则：游戏默认使用服务器 TCP 端口，以及 UDP 基础端口到
基础端口加 3。Web Dashboard 和 Telnet 默认仅限本机；若改为暴露管理接口，必须明确确认
风险。面板不会配置路由器、NAT 或端口转发。

Telnet 可以继续只在本机无密码使用，但开放其防火墙规则前必须先设置 `TelnetPassword`；
自定义 TCP 规则不能覆盖已启用的 Dashboard/Telnet 端口，请使用对应管理接口开关完成确认。

Mod 目录为 `Mods` 与 `Mods.disabled`；只能在服务器停止时切换。依赖策略为提示、严格、
忽略：提示只警告，严格会阻止有缺失或版本不符依赖的启动，忽略不检查依赖。依赖检查只
基于本地 `ModInfo.xml` 的可用元数据，不能替代 Mod 作者的完整兼容性说明。

上传的 Mod ZIP 可以是以下任一结构：顶层就是 Mod 文件夹（`ModName\ModInfo.xml`）、外面多包了
一层文件夹（例如 `Mods\ModName\ModInfo.xml`），或 `ModInfo.xml` 直接位于 ZIP 根目录（此时
以 ZIP 文件名作为 Mod 文件夹名）。

Mod ZIP 解压上限为 16 GiB；Mod 与存档整包最多 100000 个条目，解压前必须在目标磁盘
保留至少 1 GiB 余量。存档整包仍保留 256 GiB 上限，避免妨碍第三方 16K 地图。

控制台按需打开、保留有界的最近日志并在入库前脱敏；Telnet 命令只接受受限的单行命令。
面板默认仅绑定本机 `127.0.0.1`。第三方依赖的许可见 `THIRD_PARTY_NOTICES.md`。
